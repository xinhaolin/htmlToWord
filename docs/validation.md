## Twelve complex documents

All twelve synthetic fixtures were converted again through the public-SDK-backed validation tool, rendered and checked. The tool explicitly uses A4, 20 mm margins, page numbers, print media, `FooterAuto` and `SymbolCheckboxes: true` to preserve its earlier sample behavior. These two semantic options differ from zero-value SDK defaults.

- **12/12 converted**, **27 original pages**, **8 native charts with 8 XLSX workbooks**, **8 native checkbox controls**, **9 retained picture objects**.
- Source non-whitespace characters and order, key text, links, merged cells, checkbox initial state, chart categories/values/caches and workbook values passed the package checks. Footer text is included in the text-preservation checks.
- Three exported documents each received **30 additional native Word paragraphs**, without rerunning their HTML. Each expanded from 2 to 4 pages with the original content retained, producing 12 additional rendered pages.
- All **39 rendered pages were pixel-identical to the corresponding pages in the previously reviewed engine baseline**. This establishes no observed layout change for this SDK refactor under the same local environment. It is not HTML-to-Word pixel parity. Previously known fidelity differences remain.
- Both new README showcase documents were generated by an independent Go consumer, rendered and visually inspected. They are one page each. The report contains one native chart and its workbook; the checklist contains four controls, two initially checked.

Known differences include font metrics, layout-table spacing, chart style/axes, decorative backgrounds, complex CSS spanning and long-sidebar decoration. A three-page device catalogue still has a relatively sparse last page. The engine uses general DOM/computed-style strategies rather than case-name branches; this fixture set does not establish support for every possible page structure.

## Office-client evidence

An earlier independent WPS probe was opened, its unchecked checkbox was clicked, and the saved DOCX changed checkbox states from `[true, false]` to `[true, true]`. WPS recognized the chart as a native chart and retained its values `12.5` and `23` after saving.

That probe does **not** establish that WPS's full “Edit Data” workflow works: an editable data window was not successfully exercised. It also does not establish all twelve documents' interactive editing/printing behavior. Microsoft Word was not available. The SDK refactor did not repeat or expand those client checks. Current screenshots show LibreOffice renders and cannot prove control interactions.

## Remaining release gates

1. Configure a dedicated private security reporting channel; review API stability and the first version tag.
2. Keep CI passing on the declared Go/OS matrix and validate browser installation/sandbox/font requirements in deployment images.
3. Verify native chart data editing, checkbox toggling/saving and long-document editing/printing in the intended Word/WPS versions.
4. Add a broader independent corpus and sustained concurrency, CPU/RSS and cancellation-under-load measurements. No throughput target has been established by the current local run.
5. Extend unsupported features only with explicit diagnostics and regression evidence. Arbitrary scripts, animations, pixel-identical editable positioning and complete interactive Word forms are outside this preview's contract.
